# 学个鸟语 — 英语学习 App 设计文档

日期：2026-09-04
状态：已与用户逐节确认，待最终审阅

## 1. 产品定位

- **名称**：学个鸟语
- **目标用户**：高中/大学/职场人士中真正想突破流畅交流的人群。不按教材走，不面向考试。
- **能力分级**（词汇量为累计值，本 app 覆盖后三级）：

  | 阶段 | 累计词汇量 | 本阶段新词 | 学完水平 |
  |------|-----------|-----------|---------|
  | 中级 | 3000 词 | 3000 | 约高中水平，读写流畅，口语尚不流畅 |
  | 高级 | 5000 词 | 2000 | 约研究生水平，可做大部分职场交流 |
  | 专业级 | 7000 词 | 2000 | 可过雅思/托福，可留学、长期海外生活 |

  时间线校验：中级 3000÷10 词/天 ≈ 300 天；高级 2000÷6 词/天 ≈ 333 天；专业级同。符合每 1-1.5 年晋升一个阶段的目标。全 app 去重词汇总量 7000。
- **核心理念**：慢慢学，每天积累一小步，坚持 3-5 年。每 1-1.5 年晋升一个阶段。
- **每日时长**：平日 20-30 分钟；周末/节假日 10-15 分钟（只复习 + 轻量串词，不学新词）。
- **每日新词量**：中级 10 个；高级、专业级 6 个。
- **阶段侧重**：中级以背词为主、辅以读写、少量听说；高级减少新词、更多读写与听说；专业级以听说为主。配比通过每日单元素材的数量配比体现，不需要运行时逻辑。

## 2. 关键决策记录

| 决策点 | 结论 |
|--------|------|
| 内容架构 | 引擎与内容分离开发，随 app 一起打包发布；内容更新走 app 版本发布 |
| 音频 | 单词用预生成短音频；句子/对话/短文用系统 TTS |
| 付费 | 试用 + 一次性买断（iOS StoreKit 2 / Android Play Billing，端上验证，无服务器） |
| 定级 | 用户自选阶段 + 可选词汇量快速测试 |
| 备份 | 云盘自动备份（iCloud / Google Drive）+ 手动导出导入兜底 |
| 口语练习 | 纯跟读，不做发音评测 |
| 晋升 | 达标提示 + 可手动切换 |
| 词表来源 | 公开词频表（COCA / Oxford 等）筛选分级，LLM 生成释义例句后人工审核 |
| 深色模式 | v1 支持 |
| 服务器 | 无。全部功能离线可用 |

## 3. 整体架构

Flutter monorepo，三个 Dart 包 + 内容管线：

```
birdsong/
├── packages/
│   ├── srs_core/          # 纯 Dart：SRS 调度、熟悉度状态机、每日任务编排、成就判定
│   └── content_models/    # 纯 Dart：词表/每日内容的共享数据模型与 schema
├── app/                   # Flutter 应用（UI、本地库、音频、付费、备份）
│   └── assets/
│       ├── content.db     # 构建期生成的只读内容库
│       └── audio/         # 单词发音音频（按阶段分目录）
├── tools/
│   └── content_pipeline/  # 校验 + 构建脚本：JSON 源文件 → content.db
└── content_src/           # 内容源文件（JSON，人可读、可 diff、可脚本批量生成）
    ├── wordlists/         # 分级词表
    └── daily/             # 每日素材（按单元组织）
```

- `content_src/` 与 `tools/` **不随 app 发布**，仅存在于开发仓库；产物（content.db + 音频）打包进 `app/assets/`。
- `packages/` 与 `app/` 编译进 app。

### 数据库分离

| | `content.db`（只读） | `user.db`（读写，drift） |
|---|---|---|
| 内容 | 词表、例句、每日素材、音频路径 | 复习进度、熟悉度、成就、设置、购买状态 |
| 来源 | 构建期管线生成，随 app 发布 | 运行时产生 |
| 备份 | 不备份（可随 app 重建） | 只备份它 |

`content.db` 内置 `content_version`，app 启动时校验与代码期望版本匹配。

## 4. 学习模型（srs_core）

### 4.1 熟悉度 5 档（新词默认「模糊」）

| 档位 | 名称 | 含义 |
|------|------|------|
| L0 | 陌生 | 想不起来了 |
| L1 | 模糊 | 有点印象，但模棱两可 |
| L2 | 认识 | 看到能认出，但平时很少用到 |
| L3 | 熟悉 | 能主动想起、会在句子里用 |
| L4 | 牢记 | 接近母语直觉，长期记忆 |

### 4.2 艾宾浩斯阶梯（每档 2 个间隔，本档答对 2 次升档）

| 档位 | 间隔 1 | 间隔 2 | 答对 2 次后 |
|------|--------|--------|------------|
| 陌生 | 10 分钟 | 1 天 | → 模糊 |
| 模糊 | 2 天 | 4 天 | → 认识 |
| 认识 | 7 天 | 15 天 | → 熟悉 |
| 熟悉 | 1 个月 | 3 个月 | → 牢记 |
| 牢记 | — | — | 毕业，不再安排复习（只在日常素材中自然复现） |

新词从「模糊」起步，顺利路径：6 次答对、约 4 个多月毕业。10 分钟档若落在同一学习会话内，在当次会话后半段重现。

### 4.3 调档规则

1. **答对 2 次** → 升 1 档
2. **答错 1 次** → 降 2 档（下限「陌生」），且本次会话结束前重现一次（即时强化）
3. **变档后**从新档位间隔 1 重新走阶梯（该档答对计数清零）
4. **手动调档**：用户可在词书设任意档位，从该档间隔 1 开始走阶梯；手动设「牢记」= 直接毕业
5. **当日必过**：当天出现的词必须答对才算完成，答错持续重现直到答对（不设次数上限）
6. **次日强制复习**：当天新学的词、当天答错过的词，第二天必须强制复习一次（无论当前档位）；完成这次复习后，间隔阶梯照常生效。其他词仍按阶梯间隔排期
7. **积压保险阀**：待复习积压超过阈值（默认 100，可配置）时，自动减少/暂停当天新词（10 → 6 → 0），优先清积压，清完恢复

> 容量分析：整体答对率 ≥ 90-95% 时，10 新词/天的稳态复习量约 75-105 个（含次日强制复习的新词与错词），可控制在 20-30 分钟预算内；低于 85% 会超预算，保险阀兜底。

### 4.4 每日任务编排

平日会话（20-30 分钟）顺序：
1. 复习到期词（优先清空）
2. 学新词（中级 10 / 高级·专业级 6）
3. 串词巩固（用当天新词 + 近期词，从内容库取例句/对话/阅读/写作素材）

周末/节假日（10-15 分钟）：只复习到期词 + 轻量串词，不学新词。

## 5. 内容模型与管线

### 5.1 词条结构（`content_src/wordlists/*.json`）

```json
{
  "word": "abundant",
  "phonetic": "/əˈbʌndənt/",
  "pos": "adj.",
  "meaning_zh": "丰富的，充裕的",
  "audio": "advanced/abundant.mp3",
  "examples": [
    { "en": "The region has abundant natural resources.", "zh": "该地区自然资源丰富。" }
  ],
  "stage": "advanced",
  "frequency_rank": 4200
}
```

- 每词 2-3 条例句，管线批量生成、人工审核
- `frequency_rank` 决定学习顺序（高频优先）

### 5.2 每日素材（`content_src/daily/{stage}/unit_NNN.json`）

按**单元**组织（不按死日期，支持中断/补学）。每单元绑定当天新词，包含：

| 素材类型 | 内容 | 用途 |
|---|---|---|
| sentences | 当天新词串成的例句/短段 | 串词巩固、跟读 |
| dialogue | 含新词的短对话（2-4 轮） | 听力 + 跟读 |
| reading | 80-150 词短文，嵌入新词 | 阅读 |
| writing_prompt | 用新词填空/造句 | 写作 |

听说读写配比 = 单元内素材数量配比（中级多 reading/writing，专业级多 dialogue/listening）。

### 5.3 构建管线（`tools/content_pipeline/`）

1. **校验**：JSON schema、词数核对（3000/5000/7000）、音频齐全性、例句非空、单元-新词绑定完整性
2. **构建**：生成 `content.db`（只读 SQLite），音频复制到 `app/assets/audio/`

### 5.4 音频

- 单词音频：`audio/{stage}/{word}.mp3`，开发期云端 TTS 批量生成（约 15000 个，总计约 200-400MB）
- 句子/对话/短文：不存文件，运行时系统 TTS
- ⚠️ 已知问题：全打包体积偏大，实现阶段可优化（按阶段分包 / 压缩码率）

## 6. App 功能与页面流

### 6.1 首次启动（Onboarding）

欢迎页 → 选择阶段（附描述）→ [可选] 词汇量快速测试（看词选义，约 5 分钟，给推荐阶段）→ 确认阶段 → 试用/付费说明 → 首页

### 6.2 页面结构（5 Tab + 学习会话）

| 页面 | 内容 |
|---|---|
| 今日（首页） | 待复习数、新词数、预计时长；开始学习入口；连续打卡天数 |
| 学习会话 | 全屏沉浸：复习卡片 → 新词学习 → 串词巩固；答错即时重现 |
| 词书 | 按阶段浏览，可按熟悉度筛选；词详情（释义/例句/音频）；手动调整熟悉度 |
| 成就 | 徽章列表、学习统计（累计词数、毕业词数、总天数） |
| 我的 | 阶段与晋升、备份/恢复、手动导出、购买/恢复购买、设置 |

页面与交互细节待后续专项对齐。

### 6.3 学习卡片交互

- 正面：单词 + 音标 + 音频按钮；翻开后：释义 + 例句（TTS 可播）
- 自评：认识 / 不认识（驱动调档规则）
- 新词额外展示完整释义、例句，并跟读一遍（纯跟读，不评测）

### 6.4 晋升

- 达标条件：当前阶段词表学完 + 毕业词比例达标（默认 80%，可配置）
- 达标后首页弹晋升祝贺页，用户确认进入下一阶段
- 「我的」页可随时手动切换/回退，各阶段进度独立保存

### 6.5 提醒

本地通知，用户设定每日提醒时间。

## 7. 成就系统

设计原则：对抗枯燥与放弃，不制造焦虑。

- **连续打卡**：7/30/100/365/1000 天里程碑；每周 1 次补卡保护（断 1 天不清零）
- **词汇成就**：累计学习（100/500/1000/3000）、毕业词（100/500/1000）、阶段晋升、词表进度（25%/50%/75%/100%）
- **趣味成就**：早鸟/夜猫（连续 7 天早 8 点前/晚 10 点后学习）、全勤月、主题词组（依赖词表主题标签）
- **实现**：成就规则为纯数据配置（条件类型 + 阈值），`srs_core` 判定、界面展示；状态存 `user.db`

## 8. 付费

| 项 | 方案 |
|---|---|
| 试用 | 免费 7 天或限前 3 个单元（实现时定），全功能 |

## 9. 备份与换机

| 项 | 方案 |
|---|---|
| 备份对象 | 仅 `user.db`（MB 级） |

## 10. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Flutter（稳定版）+ Dart | 需求指定，一套代码双端 |
| 状态管理 | Riverpod | 社区主流、测试友好 |
| 本地数据库 | drift（SQLite） | user.db 读写 + content.db 只读，类型安全 |
| 音频播放 | just_audio | 成熟稳定 |
| 句子朗读 | flutter_tts（系统 TTS） | 零体积成本，离线可用 |
| 本地通知 | flutter_local_notifications | 学习提醒 |
| 内购 | in_app_purchase（官方插件） | 双端统一封装 |
| 测试 | flutter_test + srs_core 纯 Dart 单测 | 算法核心 100% 单测覆盖 |
| UI | v1 支持深色模式 | 夜间学习场景 |

## 11. 已知风险与后续事项

1. **音频体积**：7000 词音频全打包约 100-200MB，实现阶段优化（按阶段分包/压缩）
2. **隐私合规**：无服务器不收集数据是卖点，但上架仍需隐私政策页
3. **内容勘误**：只能随版本更新修复；v2 可加邮件反馈入口
4. **iOS 审核**：试用转买断文案需符合 Apple 指引
5. **页面交互细节**：第 6 节待后续专项对齐
